# 📘 2.1 Introducción a Git

Antes de trabajar con DevOps, CI/CD, contenedores o automatización, necesitamos herramientas que permitan **gestionar código**, **controlar versiones** y **colaborar con equipos de desarrollo**.  
Aprender **Git y GitHub** es un paso fundamental para cualquier **DevOps Engineer**, aunque puede resultar confuso si se intenta aprender demasiado de golpe o desde la perspectiva equivocada.

Esta sección está pensada para entender Git **desde el enfoque DevOps**, no desde la perspectiva de un programador tradicional.

---

# 🔍 ¿Qué es un sistema de control de versiones?

Un **sistema de control de versiones** (Version Control System – VCS) es un software que **registra los cambios** realizados en archivos y directorios a lo largo del tiempo.  
Permite:

- Recuperar **versiones anteriores**
- **Comparar cambios**
- **Colaborar** entre múltiples desarrolladores
- **Evitar pérdida** de trabajo
- Administrar **modificaciones simultáneas**

Se usa principalmente en proyectos de software, pero también para cualquier tipo de archivo que necesite historial y control colaborativo.

## 🧬 Tipos de sistemas de control de versiones

1. **Local (LVCS)**  
    Solo guarda versiones en un único ordenador.  
    Ej.: copias manuales en carpetas → _muy limitado_.
2. **Centralizado (CVCS)**  
    Hay un **servidor central** que contiene todas las versiones.  
    Los desarrolladores dependen de ese servidor.  
    Ej.: _Subversion (SVN)_.
3. **Distribuido (DVCS)**  
    Cada usuario tiene una **copia completa del repositorio**, con toda la historia.  
    Es más seguro, rápido y flexible.  
    Ej.: **Git** (el estándar actual).

---

# 🎯 ¿Para qué se usa?

En proyectos reales, varias personas trabajan en el mismo código. Un VCS permite:

- Ver quién cambió qué y cuándo
- Resolver conflictos cuando dos personas editan lo mismo
- Volver a un estado anterior sin perder trabajo
- Mantener versiones estables del proyecto
- Organizar el trabajo mediante ramas (branches)

Por eso Git es uno de los pilares de DevOps: **sin control de versiones, no existe CI/CD**.

# 🔄 Diferencias entre Git y GitHub

|Git|GitHub|
|---|---|
|Es una **herramienta**|Es una **plataforma en la nube**|
|Se instala en tu máquina|Está en internet|
|Sistema de control de versiones|Servicio para alojar repositorios Git|
|No requiere conexión|Requiere internet|
|Se usa por comandos|Tiene interfaz web y API|
|Puedes usarlo sin GitHub|GitHub no sirve sin Git|

En resumen:  
👉 **Git = el sistema de control de versiones**  
👉 **GitHub = el sitio donde guardas tus repositorios Git de forma remota**

(Lo verás igual con GitLab, Bitbucket, Azure DevOps…)

# 🛠️ Instalación y configuración básica

La forma de instalar Git depende del sistema operativo.

## 🐧 Linux

### Debian/Ubuntu

Instalar versión estable:

```
sudo apt-get install git
```

Última versión del upstream (PPA oficial):

```bash
sudo add-apt-repository ppa:git-core/ppa
sudo apt update
sudo apt install git
```
