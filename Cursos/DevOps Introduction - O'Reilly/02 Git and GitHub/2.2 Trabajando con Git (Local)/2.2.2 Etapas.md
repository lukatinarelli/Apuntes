# Etapas de Git

Para entender cómo funciona Git, es fundamental conocer sus **tres áreas principales**:

## 📁 1. Working Directory (Directorio de trabajo)

Es la carpeta donde tienes tus archivos **normales**, los que editas con tu editor de código.

En esta etapa:

- Git _detecta_ cambios, pero **no los controla todavía**.
- Archivos nuevos, modificados o eliminados están “sin seguimiento” (_untracked_) o modificados.

👉 Para mover cambios desde el Working Directory al Staging Area usamos:

```bash
git add archivo.txt
git add .          # Añade todos los cambios del directorio actual
git add --all      # Añade absolutamente todo (incluye eliminaciones)
git add -i         # Modo interactivo
```

## 📦 2. Staging Area (Área de preparación)

Aquí colocas los cambios que **quieres incluir en el próximo commit**.  
Es como una cesta donde eliges exactamente qué cambios guardar en el historial.

Características:

- Permite controlar qué se guarda y qué no.
- Puedes preparar solo partes de un archivo (modo interactivo).

👉 Para pasar los cambios del Staging Area al repositorio:

```bash
git commit -m "Mensaje del commit"
```

## 🏛️ 3. Local Repository (Repositorio local)

Es donde Git **almacena el historial** del proyecto.

Una vez ejecutas `git commit`:

- Los cambios quedan guardados permanentemente.
- Puedes ver tu historial con:

```bash
git log
```

---

# 🔍 Comandos esenciales de esta sección

|Comando|Qué hace|
|---|---|
|`git add`|Mueve cambios al staging area|
|`git commit`|Guarda los cambios en el repositorio local|
|`git status`|Muestra el estado del repositorio y sus etapas|
|`git log`|Muestra el historial de commits|
