# 📌 Introducción a Fork y Pull Requests

Cuando quieres colaborar en un proyecto del que **no eres propietario**, no puedes simplemente clonar y subir cambios.  
Para eso existen dos mecanismos esenciales de colaboración en GitHub:

**➡️ _Fork (copia personal del repositorio)_  
➡️ _Pull Request (solicitud para integrar tus cambios en el repo original)_**

---

# 🍴 ¿Qué es un _Fork_?

Un **fork** es una copia de un repositorio en tu cuenta de GitHub.  
Lo usas cuando:

- No tienes permisos de escritura en el repo original
- Quieres experimentar sin afectar al proyecto principal
- Necesitas tu propio espacio para trabajar

**Flujo típico:**

1. Haces _fork_ del repo
2. Clonas tu fork a tu PC
3. Creas una rama y haces cambios
4. Subes tus cambios a tu fork
5. Desde tu fork creas un **Pull Request** hacia el repo original

---

# 🔧 Cómo hacer un Fork

1. Abre la página del repositorio original en GitHub.
2. Haz clic en **Fork** (arriba a la derecha).
3. Selecciona tu cuenta como destino del fork.
4. GitHub creará una copia del repositorio en tu perfil.

---

# 🧪 Trabajar con tu Fork

Clona tu fork:

```bash
git clone https://github.com/TU-USUARIO/NOMBRE-DEL-FORK
```

Crea una nueva rama:

```bash
git checkout -b mi-feature
```

Haz cambios, añade y confirma:

```bash
git add .
git commit -m "Añadida nueva funcionalidad"
git push origin mi-feature
```

---

# 🔄 Qué es un Pull Request (PR)

Un **Pull Request** es una solicitud para que el propietario del repositorio revise tus cambios y decida si integrarlos.

Con un PR puedes:

- Solicitar revisión
- Conversar sobre los cambios
- Recibir comentarios
- Hacer más commits hasta que esté listo
- Finalmente, fusionarlo al repo original

---

# 📬 Cómo crear un Pull Request

1. Ve a tu fork en GitHub.
2. GitHub te sugerirá comparar tu rama con el repo original.
3. Haz clic en **Pull Request**.
4. Escribe un título claro y una descripción.
5. Envíalo.

Los mantenedores revisarán, pedirán cambios o lo aceptarán.

---

# 🔁 Mantener tu Fork actualizado

El repo original seguirá recibiendo cambios, así que tu fork puede quedar desactualizado.  
Lo habitual es añadir un _remote_ adicional:

```bash
git remote add upstream https://github.com/ORIGINAL-OWNER/REPO
```

Actualizar tu fork:

```bash
git fetch upstream
git merge upstream/main
```

O usando rebase:

```bash
git rebase upstream/main
```

_(Esto se explica más en la sección de ramas y rebase.)_

---

# ✔️ Resumen rápido

- **Fork:** copia personal del repo.
- **Branch:** donde trabajas tus cambios.
- **Pull Request:** pides que tu trabajo se fusione.
- **Mantener fork actualizado:** conectar con el repo original.
