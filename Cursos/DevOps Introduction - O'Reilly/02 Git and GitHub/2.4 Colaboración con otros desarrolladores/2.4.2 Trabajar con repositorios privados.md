# 🔒 Introducción a repositorios privados

Cuando trabajas en proyectos que **no quieres que sean públicos**, GitHub permite crear **repositorios privados**.  
Solo las personas que **autorizas como colaboradores** pueden ver o modificar el código.

Esto es muy útil para:

- Proyectos corporativos    
- Código en desarrollo que aún no debe ser público    
- Trabajo en equipo con permisos controlados    

---

# 👥 Añadir colaboradores a un repositorio privado

1. Abre tu repositorio privado en GitHub.    
2. Haz clic en **Settings** (Configuración) → **Collaborators and Teams**.    
3. Haz clic en **Add people**.    
4. Escribe el **nombre de usuario o correo** de la persona que quieres invitar.    
5. Selecciona el **nivel de permisos**:    
    - **Read** → solo lectura        
    - **Triage** → gestión de issues y PRs        
    - **Write** → lectura y escritura (commits, branches, PR)        
    - **Maintain** → administrar configuración del repo        
    - **Admin** → control total sobre el repositorio        
6. Haz clic en **Add** para enviar la invitación.    

> La persona invitada recibirá un correo y deberá **aceptar la invitación** para poder colaborar.

# 🔧 Clonar y trabajar con repos repositorios privados

Para clonar un repo privado necesitas **autenticación**, ya sea:

- HTTPS con **token personal**    
- SSH con tu **clave pública registrada en GitHub**    

Ejemplo con HTTPS + token:

```bash
git clone https://github.com/TU-USUARIO/NOMBRE-REPO.git
Username: TU-USUARIO
Password: TU-TOKEN
```

Ejemplo con SSH:

```bash
git clone git@github.com:TU-USUARIO/NOMBRE-REPO.git
```

Una vez clonado, el flujo de trabajo es idéntico al de repositorios públicos:

```bash
git add .
git commit -m "Cambios en mi branch"
git push origin mi-branch
```

---

# 🛡️ Control de acceso y buenas prácticas

- **No compartas tu token ni tu clave SSH**    
- Crea ramas para cada nueva funcionalidad y usa PRs para fusionarlas    
- Configura **branches protegidas** para las ramas críticas (se explicará en la siguiente nota)    
- Revisa los permisos de los colaboradores periódicamente    

---

# ✔️ Resumen rápido

- Los repositorios privados permiten **control total sobre quién ve o modifica el código**.    
- Se añaden colaboradores con niveles de permisos específicos.    
- Clonar y subir cambios requiere autenticación.    
- Mantén buenas prácticas con ramas, PRs y protección de ramas críticas.
