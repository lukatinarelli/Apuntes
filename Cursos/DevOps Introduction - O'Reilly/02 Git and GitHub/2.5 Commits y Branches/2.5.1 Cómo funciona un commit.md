# ✨ Introducción a los Commits

Un **commit** en Git es como un **“punto de control”** en el historial de tu proyecto.  
Cada commit guarda:

- Los **cambios realizados** en los archivos    
- Quién los hizo (**autor**)    
- Cuándo se hicieron (**timestamp**)    
- Un **mensaje descriptivo** que explica qué cambios contiene    

> [!TIP]
> Piensa en un commit como una **foto del proyecto** en un momento específico.

---

# 💾 Crear un commit

Antes de hacer un commit, debes **añadir los archivos al área de staging**:

```bash
git add archivo.txt      # Añade un archivo específico
git add .                # Añade todos los archivos modificados
git add -i               # Interfaz interactiva para seleccionar archivos
```

Luego haces el commit:

```bash
git commit -m "Descripción clara de los cambios"
```

Opciones útiles:

- `-a` → incluye automáticamente todos los archivos **modificados y rastreados**    
- `--amend` → modificar el último commit (útil si olvidaste algo)    

Ejemplo:

```bash
git commit -am "Arreglado bug en el flujo de login"
```

---

# 🔍 Qué contiene un commit

Cada commit tiene:

- **SHA-1 hash** → identificador único (ej.: `e259ac5`)    
- **Autor y fecha** → quién hizo los cambios y cuándo    
- **Mensaje del commit** → resumen de los cambios    
- **Referencia a cambios previos** → enlaza commits en el historial    

Puedes verlo con:

```bash
git log
```

O con formato resumido:

```bash
git log --oneline --graph --all
```

---

# 🧠 Buenas prácticas al hacer commits

1. Haz **commits pequeños y claros**.    
2. Escribe mensajes descriptivos y en tiempo presente, por ejemplo:    
    - ✅ “Arregla error en validación de email”        
    - ❌ “Arreglos varios”        
3. Confirma solo **cambios relacionados entre sí**.    
4. Haz commits **frecuentes**, no de semanas de trabajo acumulado.    

---

# 🔄 Flujo típico con commits en DevOps

1. Trabajas en tu rama de feature:    

```bash
git checkout -b feature/nueva-funcionalidad
```

2. Haces cambios en archivos.    
3. Añades al staging:    

```bash
git add .
```

4. Commit con mensaje claro:    

```bash
git commit -m "Añadida validación de contraseña"
```

5. Actualizas con cambios remotos antes de pushear:    

```bash
git pull --rebase origin main
```

6. Pusheas tus commits al remoto:    

```bash
git push origin feature/nueva-funcionalidad
```

---

# ✔️ Resumen rápido

- Un **commit** es un punto de control en Git.    
- Siempre añade cambios al **staging** antes de confirmar.    
- Haz **mensajes claros y concisos**.    
- Haz commits **pequeños y frecuentes**.    
- Antes de pushear, actualiza tu rama con el remoto (`pull --rebase`).
