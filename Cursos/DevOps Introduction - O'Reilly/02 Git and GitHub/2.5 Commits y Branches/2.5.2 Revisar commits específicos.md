# 🔍 Introducción a revisar commits

En Git, cada commit representa un **estado del proyecto**.  
Revisar commits específicos te permite:

- Ver qué cambios se hicieron    
- Entender quién los hizo y cuándo    
- Comparar versiones para detectar errores    
- Auditar el historial de un proyecto    

Es una herramienta clave para **colaborar en equipo** y **mantener la trazabilidad**.

---

# 📄 Comandos básicos para inspeccionar commits

## 1️⃣ `git log` – Ver historial de commits

```bash
git log
```

Muestra:

- SHA-1 del commit    
- Autor    
- Fecha    
- Mensaje del commit    

Opciones útiles:

```bash
git log --oneline          # Historial resumido (una línea por commit)
git log --graph --all      # Historial con ramas y merges
git log -p                 # Muestra los cambios (diff) de cada commit
```

## 2️⃣ `git show` – Ver un commit específico

```bash
git show SHA_DEL_COMMIT
```

- Muestra **detalles completos** del commit:    
    - Archivos modificados        
    - Cambios línea por línea (diff)        
    - Autor y fecha        

Ejemplo:

```bash
git show e259ac5
```

## 3️⃣ `git diff` – Comparar cambios

### a) Cambios no confirmados (working directory vs staging)

```bash
git diff
```

### b) Cambios staged vs último commit

```bash
git diff --staged
```

### c) Cambios entre commits

```bash
git diff SHA1 SHA2
```

> [!NOTE]
> Esto permite ver exactamente **qué líneas se añadieron, modificaron o eliminaron** entre dos commits.

---

# 🧠 Buenas prácticas

- Usa `git log --oneline --graph` para **visualizar la historia de forma rápida**.    
- Cuando revises un commit, **lee el mensaje y los cambios línea a línea** para entender su impacto.    
- Comparar commits antes de un merge o push ayuda a **evitar errores**.    

---

# ✔️ Resumen rápido

- `git log` → ver historial de commits    
- `git show` → detalles de un commit específico    
- `git diff` → comparar cambios entre estados o commits    
- Revisar commits es clave para **control de calidad y colaboración**
