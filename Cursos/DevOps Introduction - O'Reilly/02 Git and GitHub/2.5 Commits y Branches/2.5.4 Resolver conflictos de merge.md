# ⚔️ Introducción a los conflictos de merge

Un **conflicto de merge** ocurre cuando Git **no puede combinar automáticamente** los cambios de dos ramas porque modifican la misma línea o área de un archivo.  
Esto es común al trabajar en **equipos grandes** o cuando varias ramas avanzan en paralelo.

> No te asustes: los conflictos son normales y **se pueden resolver manualmente**.

---

# 🔍 Detectar un conflicto de merge

Si intentas fusionar (`merge`) y hay conflicto, Git muestra un mensaje como:

```
Auto-merging archivo.txt
CONFLICT (content): Merge conflict in archivo.txt
Automatic merge failed; fix conflicts and then commit the result.
```

También puedes usar:

```bash
git status
```

Verás algo como:

```
Unmerged paths:
  (use "git add <file>..." to mark resolution)
	modificado por ambos: archivo.txt
```

---

# ✏️ Resolver un conflicto

1. Abre el archivo en conflicto. Verás marcadores:    

```text
<<<<<<< HEAD
Tus cambios locales
=======
Cambios en la rama que estás fusionando
>>>>>>> rama-remota
```

2. Decide qué contenido conservar:    

- Solo tus cambios    
- Solo los cambios remotos    
- Una combinación de ambos    

3. Borra los marcadores `<<<<<<<`, `=======`, `>>>>>>>` y guarda el archivo.    

---

# ✅ Marcar conflicto como resuelto

Después de editar y guardar:

```bash
git add archivo.txt
```

Git ahora sabe que el conflicto está resuelto.

---

# 🔄 Terminar el merge

Si estabas en un merge normal:

```bash
git commit -m "Resuelto conflicto en archivo.txt"
```

Si estabas en un **rebase**:

```bash
git rebase --continue
```

> Git aplicará los siguientes commits pendientes y completará el rebase.

---

# 💡 Buenas prácticas para evitar conflictos

- Haz **pull --rebase** antes de pushear    
 Trabaja en **ramas separadas** para cada funcionalidad
    
- Haz commits **pequeños y frecuentes**    
- Comunica cambios importantes al equipo    

---

# ✔️ Resumen rápido

- Los conflictos ocurren cuando **dos ramas modifican lo mismo**    
- Se detectan con `git status` o al hacer `merge`    
- Se resuelven **editando los archivos en conflicto**    
- Se marca la resolución con `git add`    
- Se completa con `git commit` o `git rebase --continue`
