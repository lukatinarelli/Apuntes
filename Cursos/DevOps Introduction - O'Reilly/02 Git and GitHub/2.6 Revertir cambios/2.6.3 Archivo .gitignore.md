# 🙈 Archivo .gitignore

El archivo `.gitignore` es un archivo de texto plano que le indica a Git qué archivos o directorios **debe ignorar intencionalmente**.

Estos archivos generalmente son:

- **Artefactos de compilación:** Carpetas `bin/`, `build/`, `dist/`.
- **Dependencias descargadas:** `node_modules/`, `venv/`.
- **Archivos temporales del sistema:** `.DS_Store` (Mac), `Thumbs.db` (Windows).
- **Configuraciones del IDE:** `.vscode/`, `.idea/`.
- **Archivos con datos sensibles:** `.env`, credenciales.

> [!NOTE]
> El archivo .gitignore debe estar comiteado en el repositorio para que todos los desarrolladores del equipo ignoren los mismos archivos.

---

# 📝 Sintaxis Básica

Se utiliza un patrón de coincidencia estándar (globbing).

```.gitignore
# 1. Ignorar archivos específicos
secrets.txt

# 2. Ignorar por extensión (todos los logs)
*.log

# 3. Ignorar directorios completos (y su contenido)
node_modules/
temp/

# 4. Excepciones (Ignorar todo EXCEPTO este archivo)
# Ignora todos los .md, pero NO ignores el README.md
*.md
!README.md

# 5. Comentarios
# Las líneas que empiezan con # son ignoradas
```

# ⚠️ Problema común: Ignorar archivos ya rastreados

Un error muy frecuente es crear el `.gitignore` **después** de haber hecho commit de archivos que queríamos ignorar.

> [!WARNING]
> Si un archivo ya está en el repositorio (trackeado), Git seguirá rastreando sus cambios aunque lo agregues al .gitignore. Git solo ignora archivos untracked.

## Solución: Limpiar la caché (Revertir el rastreo)

Para hacer que el `.gitignore` surta efecto en archivos que ya subiste, debes sacarlos del índice (staging area) sin borrarlos de tu disco:

```Bash
# 1. Asegúrate de tener el .gitignore actualizado

# 2. Elimina el archivo del rastreo de Git (se mantiene en tu disco)
git rm --cached archivo_que_quiero_ignorar.log

# 3. Si es una carpeta completa
git rm -r --cached carpeta_build/

# 4. Haz commit del cambio
git commit -m "Dejar de rastrear archivos ignorados"
```

A partir de ahora, Git respetará la regla del `.gitignore`.

# 🛡️ Buenas Prácticas en DevOps

## 1. La Seguridad ante todo

Jamás subas contraseñas, tokens de API o claves privadas.

- **Regla:** Añade `*.env`, `config.js` (si tiene claves) o claves `.pem` al `.gitignore` antes de hacer el primer commit.

## 2. Generadores Automáticos

No escribas el archivo desde cero. Existen herramientas que generan plantillas estándares según tu tecnología (Java, Python, Node, Terraform, etc.).

- Sitio recomendado: [gitignore.io](https://www.toptal.com/developers/gitignore)

## 3. Gitignore Global

Puedes configurar un gitignore para **todos** tus proyectos en tu máquina (útil para archivos de sistema operativo o de tu editor de texto personal).

```Bash
# Configura un archivo global en tu home
git config --global core.excludesfile ~/.gitignore_global
```

# ✔️ Resumen rápido

- **.gitignore:** Lista negra de archivos que Git no debe ver.
- **Ubicación:** Raíz del proyecto.
- **Sintaxis:** `*.log` (extensiones), `/carpeta` (directorios).
- **Importante:** Si el archivo ya tiene historial, usa `git rm --cached` para que empiece a ser ignorado.
