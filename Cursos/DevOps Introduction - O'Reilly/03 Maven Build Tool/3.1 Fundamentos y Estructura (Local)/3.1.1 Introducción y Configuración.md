# ☸️ 1. Maven en el Flujo DevOps

Mientras que el desarrollador usa Maven en su máquina para "ver si funciona", el Ingeniero DevOps lo utiliza para **industrializar** el proceso.

Una vez que el desarrollador hace `git push`, el código llega al repositorio (GitHub/GitLab). Aquí comienza la responsabilidad del DevOps:

1. **Descarga de Dependencias:** El servidor de Build (ej. Jenkins) usa Maven para bajar librerías limpias, asegurando que no falte nada.
2. **Generación de Artefactos:**
    - _Concepto Clave:_ **Artifact (Artefacto)**. Es el resultado tangible del código fuente compilado (ej. un archivo `.jar` o `.war`).
    - Maven transforma "Source Code" ➡️ "Artifact".
3. **Unit Testing:** Maven ejecuta los tests automáticos (`mvn test`) antes de generar el artefacto. Si fallan, se detiene el pipeline.
4. **Deployment:** Maven puede subir el artefacto resultante a un repositorio de binarios (Nexus/Artifactory) o desplegarlo en un servidor.

# ☕ 2. Instalación de Java (JDK)

Maven está escrito en Java y sirve para proyectos Java. Por tanto, es **obligatorio** tener el JDK (Java Development Kit) instalado. Sin Java, Maven no funciona.

## Paso a paso (Windows):

1. **Descargar:** Ir a la web de Oracle y descargar el **JDK** (ej. Java 15 o superior) para Windows x64.
2. **Instalar:** Ejecutar el `.exe` con permisos de administrador. Por defecto se instala en `C:\Program Files\Java\jdk-...`.

## ⚠️ Configuración de Variables de Entorno

Para que Maven (y cualquier herramienta DevOps) encuentre Java, necesitas configurar las variables del sistema:

1. **JAVA_HOME:**
    - Crear nueva variable de sistema.
    - Nombre: `JAVA_HOME`.
    - Valor: Ruta raíz de instalación (ej. `C:\Program Files\Java\jdk-15.0.2`). _Ojo: Sin la carpeta `bin`_.
2. **Path:**
    - Editar la variable `Path`.
    - Añadir nueva línea: `%JAVA_HOME%\bin` (o la ruta completa a la carpeta `bin`).

## Verificación

Abrir una terminal (CMD o PowerShell) y ejecutar:

```Bash
java -version
javac -version
```

Si ambos comandos devuelven la versión, Java está listo.

# 🌑 3. Instalación de Eclipse IDE

Aunque como DevOps trabajaremos mucho con terminal y servidores, necesitamos un IDE para **simular el rol del desarrollador** (crear código de prueba, editar `pom.xml` con autocompletado).

- **Eclipse:** Es el IDE estándar "de facto" para Java en muchas empresas enterprise.
- **Workspace:** Al iniciar, Eclipse pedirá un "Workspace". Es simplemente la carpeta donde se guardarán tus proyectos. Se recomienda crear una carpeta limpia (ej. `C:\DevOps_Projects`).
