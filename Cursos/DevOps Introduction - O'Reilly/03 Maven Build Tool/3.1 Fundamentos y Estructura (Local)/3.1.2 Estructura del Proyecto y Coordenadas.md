# 📦 Estructura del Proyecto y Coordenadas (GAV)

Para que Maven pueda gestionar un proyecto, necesita saber **quién es** (Coordenadas) y **dónde están las cosas** (Estructura).

# 📍 1. Coordenadas Maven (GAV)

Al igual que en Google Maps necesitas coordenadas para encontrar un lugar, en Maven (y en los repositorios como Nexus/Artifactory) necesitas **GAV** para identificar un artefacto de software de forma única.

|**Coordenada**|**Descripción**|**Ejemplo**|
|---|---|---|
|**G**roupId|Identificador de la organización o empresa. Suele ser el dominio web invertido.|`com.miempresa.infra`|
|**A**rtifactId|El nombre del proyecto o módulo específico.|`api-pagos`|
|**V**ersion|La versión actual del desarrollo.|`1.0.0-SNAPSHOT`|

> [!NOTE]
> **SNAPSHOT:** Significa que es una versión en desarrollo (inestable). Cuando está lista para producción, se quita el sufijo (ej. 1.0.0).

# 🐧 2. Crear Proyecto en Linux (Archetypes)

Maven utiliza Archetypes (Arquetipos), que son plantillas predefinidas para generar el esqueleto del proyecto automáticamente.

## Comando para generar el proyecto

Ejecuta esto en tu terminal Linux para crear una app Java básica sin tocar código:

```Bash
mvn archetype:generate \
    -DgroupId=com.demo.empresa \
    -DartifactId=mi-primera-app \
    -DarchetypeArtifactId=maven-archetype-quickstart \
    -DinteractiveMode=false
```

- `archetype:generate`: El comando para crear desde plantilla.
- `maven-archetype-quickstart`: La plantilla más básica (Hola Mundo).
- `-DinteractiveMode=false`: Para que no te haga preguntas y lo cree del tirón.

# 📂 3. Estructura de Directorios Estándar

Una vez ejecutado el comando, verás una carpeta `mi-primera-app`. Maven **exige** que los archivos estén en sitios específicos. Si entras (`cd mi-primera-app`) y haces un `tree`, verás esto:

```Plaintext
mi-primera-app/
├── pom.xml               <-- 📜 EL CEREBRO (Configuración y GAV)
└── src/
    ├── main/
    │   └── java/         <-- Aquí vive el CÓDIGO de la aplicación
    └── test/
        └── java/         <-- Aquí viven los TESTS automáticos
```

## ¿Por qué esta estructura?

Maven separa estrictamente el código funcional (`main`) del código de prueba (`test`).

- Cuando compilas para producción, Maven coge **solo** lo que hay en `main`.
- Cuando ejecutas tests en Jenkins, Maven mira en `test`.

> [!IMPORTANT]
> **La carpeta target:** Al principio no existe. Se creará automáticamente cuando compiles el proyecto. Ahí es donde aparecerá el archivo final (.jar o .war) listo para desplegar.

---

# ☸️ Contexto DevOps

Como Ingeniero DevOps, nunca debes cambiar esta estructura manualmente.

Los pipelines de CI/CD (Jenkins, GitLab CI) esperan encontrar el código en src/main/java y el archivo pom.xml en la raíz. Si los mueves, el pipeline fallará.
