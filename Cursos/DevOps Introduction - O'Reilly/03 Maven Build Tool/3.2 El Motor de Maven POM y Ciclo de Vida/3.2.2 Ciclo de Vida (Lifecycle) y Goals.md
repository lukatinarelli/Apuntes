# 🔄 Ciclo de Vida (Lifecycle) y Goals

Construir software no es solo "compilar". Es un proceso paso a paso: limpiar basura anterior, compilar código, probarlo, empaquetarlo y guardarlo.

Maven estandariza este proceso mediante el concepto de Build Lifecycle.

# 🧬 1. ¿Qué es el Lifecycle?

El Lifecycle es una secuencia ordenada de fases.

Cuando le pides a Maven que haga algo, no salta directamente a ese paso; ejecuta todos los pasos anteriores en orden hasta llegar al que pediste.

Existen 3 Ciclos de Vida principales:

1. **Clean:** Limpieza del proyecto.
2. **Default:** Construcción y despliegue (El principal).
3. **Site:** Generación de documentación (Raramente usado en DevOps).

---

# 🎯 2. Default Lifecycle (El Camino Crítico)

Este es el ciclo que usaremos el 99% del tiempo. Sus fases (Goals) se ejecutan en este orden estricto:

|**Orden**|**Fase (Goal)**|**Descripción**|
|---|---|---|
|1|`validate`|Verifica que el proyecto es correcto y tiene toda la info necesaria.|
|2|`compile`|Compila el código fuente (`.java` ➡️ `.class`).|
|3|`test`|Ejecuta las pruebas unitarias (JUnit) usando el código compilado.|
|4|**`package`**|Empaqueta el código compilado en un formato distribuible (`.jar` o `.war`). El archivo se genera en la carpeta `target/`.|
|5|**`install`**|Copia el paquete (`.jar`) a tu **Repositorio Local** (`~/.m2`). Ahora otros proyectos en tu máquina pueden usarlo.|
|6|**`deploy`**|Copia el paquete final al **Repositorio Remoto** (Nexus/Artifactory) para compartirlo con otros desarrolladores o servidores.|

---

# 🧹 3. Clean Lifecycle

Antes de construir, es vital asegurarse de que no estamos usando archivos viejos de una compilación anterior.

- **Goal:** `clean`
- **Acción:** Borra la carpeta `target/` completa.

> [!WARNING]
> Si no ejecutas clean, Maven podría mezclar clases nuevas con clases viejas, provocando errores "fantasma" que son difíciles de depurar.

---

# ⚡ 4. Ejecución Secuencial (La Regla de Oro)

Maven es secuencial. Si ejecutas una fase tardía, Maven asume que quieres ejecutar todas las anteriores.

**Ejemplo:** Si ejecutas `mvn install`:

1. Maven ejecuta `validate`...
2. luego `compile`...
3. luego `test`...
4. luego `package`...
5. y finalmente `install`.

**Ejemplo:** Si ejecutas `mvn compile`:

1. Solo ejecuta `validate` y `compile`. (No testea ni genera el jar).

---

# 🛠️ 5. Comandos Maven para DevOps (Best Practices)

En un pipeline de CI/CD (Jenkins, GitLab CI), rara vez usamos un solo goal. Combinamos el ciclo de limpieza con el de construcción.

## El Comando Estándar

```Bash
mvn clean install
```

Este es el comando más común ("La vieja confiable").

1. **Limpia** residuos anteriores (`clean`).
2. **Compila** y pasa los **Tests**.
3. **Empaqueta** el binario.
4. Lo guarda en tu caché local (`install`).

## El Comando de "Solo Empaquetar"

Si no quieres llenar tu disco duro (`.m2`) con versiones de prueba, o estás en un entorno efímero:

```Bash
mvn clean package
```

Genera el archivo en la carpeta `target/` y se detiene ahí.

## El Comando de Producción

Cuando el código está listo para salir al mundo:

```Bash
mvn clean deploy
```

Esto sube el binario a Nexus/Artifactory para que los servidores de producción puedan descargarlo.

---

# 📂 6. La Carpeta `target/`

Es el directorio de salida (Output Directory).

- Se crea automáticamente al compilar.
- Se borra automáticamente al hacer `mvn clean`.
- **Aquí encontrarás tu tesoro:** El archivo `.jar` o `.war` final estará dentro de `target/`.
