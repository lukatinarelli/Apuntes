# 🏗️ Integración Maven + Jenkins (CI/CD)

Hasta ahora ejecutábamos mvn clean install manualmente en la terminal. En un entorno DevOps real, esto nunca se hace así.

Utilizamos un servidor de Integración Continua (Jenkins) para orquestar todo el proceso automáticamente cada vez que un desarrollador sube código.

---

# 🏛️ 1. Arquitectura: Master & Agent (Slave)

En este laboratorio configuramos una arquitectura distribuida, que es el estándar en la industria. No ejecutamos el trabajo en el servidor principal de Jenkins, sino que delegamos la tarea pesada al servidor Maven que configuramos en la sección anterior.

- **Jenkins Server (Master):** El "cerebro". Gestiona la interfaz, los usuarios y programa los trabajos.
- **Maven Build Server (Agent/Slave):** El "músculo". Es el servidor Linux donde instalamos Java y Maven en la sección 3.3. Aquí es donde realmente se compila el código.

---

# ⚙️ 2. Configuración del Agente (Maven Server)

Para que Jenkins (Master) pueda conectarse y mandar órdenes al Maven Server (Agent), necesitamos preparar el terreno a nivel de sistema operativo.

## A. Crear usuario dedicado

En el **Maven Server**, no debemos usar `root`. Creamos un usuario `jenkins`:

```Bash
# 1. Crear usuario
sudo useradd jenkins

# 2. Asignar contraseña
sudo passwd jenkins

# 3. Dar permisos de sudo (opcional pero recomendado para setups iniciales)
# Añadir al archivo sudoers o grupo wheel
```

## B. Habilitar conexión SSH por contraseña

Por defecto, AWS bloquea la autenticación por contraseña (solo permite llaves `.pem`). Para conectar Jenkins fácilmente, habilitamos la contraseña:

1. Editar `/etc/ssh/sshd_config`.
2. Cambiar `PasswordAuthentication no` a `yes`.
3. Reiniciar servicio: `sudo service sshd reload`.

---

# 🔗 3. Conectar el Nodo en Jenkins

Ahora vamos a la interfaz web de Jenkins (`Manage Jenkins` -> `Manage Nodes and Clouds` -> `New Node`).

## Configuración del Nodo:

- **Name:** `MavenBuildServer`
- **Remote root directory:** `/home/jenkins` (El workspace donde se clonará el código).
- **Launch method:** "Launch agent via SSH".
- **Host:** IP Privada del Maven Server (si están en la misma red AWS) o IP Pública.
- **Credentials:** Añadir usuario/pass (`jenkins`/`****`) que creamos antes.
- **Host Key Verification Strategy:** "Non verifying verification strategy" (Para evitar problemas de llaves en laboratorios).

> [!CHECK]
> Si todo va bien, el agente aparecerá como "Synchronized" o conectado. Jenkins ya tiene control sobre ese servidor.

---

# 🛠️ 4. Global Tool Configuration

Este es un paso donde fallan muchos principiantes.

Jenkins sabe conectarse al servidor, pero no sabe dónde instalaste Maven ni Java en ese servidor. Tienes que decírselo explícitamente.

Ruta: `Manage Jenkins` -> `Global Tool Configuration`.

1. **JDK:**
    - Desmarcar "Install automatically".
    - **JAVA_HOME:** Poner la ruta del servidor agente (ej. `/usr/lib/jvm/java-1.8.0...` o la que configuraste en el `.bash_profile`).
2. **Maven:**
    - Desmarcar "Install automatically".
    - **MAVEN_HOME:** Poner la ruta `/opt/apache-maven-...` (donde descomprimiste el tar.gz en la sección 3.3).

---

# 👷 5. Crear el Job de Construcción

Finalmente, creamos la tarea automatizada.

1. **Nuevo Item:** "Maven-Project-Build".
2. **Tipo:** Maven Project (o Freestyle Project si no tienes el plugin específico).
3. **Restrict where this project can be run:** ✅ (Importante).
    - **Label Expression:** `MavenBuildServer` (Obligamos a que corra en nuestro agente, no en el master).
4. **Source Code Management (Git):**
    - URL: La URL de tu repo GitHub (`https://github.com/usuario/mi-web-app.git`).
5. **Build (Goals):**    
    - `clean install`

## Ejecución

Al pulsar **"Build Now"**:

1. Jenkins Master despierta al Agente.    
2. El Agente clona el repo de GitHub en `/home/jenkins/workspace`.
3. El Agente busca el `pom.xml`.  
4. El Agente ejecuta `mvn clean install`.
5. El resultado (`.war`) se guarda en el workspace del Agente.

---

# ✔️ Resumen del Módulo Maven

Hemos pasado de compilar a mano en Eclipse a tener un flujo CI/CD profesional:

1. **Local:** El desarrollador tiene el código y el `pom.xml`.
2. **Git:** Sube los cambios al repositorio.
3. **Jenkins:** Detecta cambios (o se lanza manual).
4. **Agente Maven:** Descarga dependencias, compila y genera el `.war`.  
5. **Resultado:** Tenemos un artefacto listo para desplegar (que es lo que veremos en el módulo de Tomcat/Docker).
