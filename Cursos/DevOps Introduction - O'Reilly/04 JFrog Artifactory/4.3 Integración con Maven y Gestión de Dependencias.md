# 🔌 Integración con Maven y Gestión de Dependencias

Una vez instalado el servidor, debemos configurar nuestro entorno de desarrollo (Maven) para usarlo. Esto implica dos flujos:

1. **Resolución (Download):** Descargar librerías desde Artifactory.
2. **Despliegue (Upload):** Subir nuestros `.jar` compilados a Artifactory.

---

# 🗄️ 1. Tipos de Repositorios en Artifactory

Artifactory organiza los archivos en tres categorías distintas. Es vital entenderlas para saber dónde buscar las cosas.

|**Tipo**|**Descripción**|**Ejemplo**|
|---|---|---|
|**Local**|Repositorios físicos alojados en tu servidor. Aquí guardas los `.jar` que tu equipo compila.|`libs-snapshot-local`, `libs-release-local`|
|**Remote**|Un proxy (espejo) de un repositorio externo (Internet). No subes cosas aquí; Artifactory las cachea cuando las pides.|`jcenter`, `maven-central`|
|**Virtual**|Un "repositorio lógico" que agrupa varios locales y remotos bajo una sola URL.|`libs-release` (Agrupa local + remote)|

> [!TIP]
> Virtual es lo que configuras en Maven. Así, Maven busca en un solo sitio y Artifactory se encarga de buscar dentro, ya sea en local o en remoto.

---

# 🔐 2. Autenticación (settings.xml)

Artifactory es privado. Maven necesita credenciales para poder leer o escribir.

Estas credenciales NUNCA van en el código del proyecto (pom.xml), sino en el archivo global de configuración de tu usuario.

**Archivo:** `~/.m2/settings.xml` (Linux/Mac) o `%USERPROFILE%\.m2\settings.xml` (Windows).

```XML
<settings>
    <servers>
        <server>
            <id>central</id>
            <username>admin</username> <password>PASSWORD_O_API_KEY</password>
        </server>
        <server>
            <id>snapshots</id>
            <username>admin</username>
            <password>PASSWORD_O_API_KEY</password>
        </server>
    </servers>
</settings>
```

> [!NOTE]
> **Generador Automático:** En la interfaz de Artifactory, puedes hacer clic en el botón "Set Me Up" sobre un repositorio. Te generará automáticamente estos snippets XML listos para copiar y pegar.

---

# 📤 3. Configurar el Proyecto (pom.xml)

Ahora le decimos al proyecto **dónde** debe subir los artefactos resultantes del build. Esto se hace con la etiqueta `<distributionManagement>`.

**Archivo:** `pom.xml` (en la raíz de tu proyecto)

```XML
<project>
    <distributionManagement>
        <repository>
            <id>central</id> <name>libs-release-local</name>
            <url>http://<IP-ARTIFACTORY>:8081/artifactory/libs-release-local</url>
        </repository>
        <snapshotRepository>
            <id>snapshots</id> <name>libs-snapshot-local</name>
            <url>http://<IP-ARTIFACTORY>:8081/artifactory/libs-snapshot-local</url>
        </snapshotRepository>
    </distributionManagement>
</project>
```

---

# 🚀 4. Despliegue (Deploy)

Con todo configurado, el ciclo de vida de Maven ahora termina enviando el archivo al servidor remoto.

## Comando:

```Bash
mvn deploy
```

## ¿Qué ocurre internamente?

1. **Validación:** Maven comprueba si es una versión `SNAPSHOT` (desarrollo) o `RELEASE` (final).
2. **Autenticación:** Lee `settings.xml` para coger usuario/pass.
3. **Upload:** Sube el `.jar` y el `.pom` a la URL definida en `distributionManagement`.
4. **Resultado:** Si vas a la Web UI de Artifactory, verás tu archivo en el repositorio `libs-snapshot-local` o `libs-release-local`.

---

# 🔄 5. Verificación de Caché (Proxy)

Para comprobar que Artifactory está funcionando como proxy de Internet:

1. Borra tu caché local: `rm -rf ~/.m2/repository`.
2. Ejecuta un build: `mvn verify`.
3. Observa los logs: Verás `Downloading from... <TU-IP-ARTIFACTORY>`.
4. Observa Artifactory: En la sección **Remote Repositories**, verás que se han cacheado librerías como `junit`, `spring`, etc.
