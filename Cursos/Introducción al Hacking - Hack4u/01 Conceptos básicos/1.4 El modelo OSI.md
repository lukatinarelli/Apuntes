# Introducción:

El **modelo OSI (Open Systems Interconnection)** es una forma estandarizada de describir _cómo viajan los datos_ desde un dispositivo hasta otro.

Divide todo el proceso en **7 capas**, donde cada una cumple funciones concretas y depende de la inferior para construir la comunicación final.

> [!IMPORTANT]  
> Para un pentester, entender el modelo OSI no es un tema “académico”: es la forma de saber **dónde buscar vulnerabilidades**, **qué herramientas usar** en cada capa y **cómo viajan los paquetes que analizas**.

---

# 🔹 ¿Por qué existen las capas OSI?

Porque en una comunicación real intervienen muchos elementos: el hardware, los protocolos, las rutas, el formato de los datos, la aplicación…  
Las capas OSI permiten separar responsabilidades y evitar que un cambio en un nivel afecte a todos los demás.

> [!NOTE]  
> El modelo OSI **no es un protocolo**, sino un mapa que organiza _cómo deberían funcionar los protocolos_ dentro de una red.

---

# 🪜 Las 7 capas del modelo OSI (de la 1️⃣ a la 7️⃣)

## 1️⃣ Capa Física (Physical Layer)

Es el nivel más bajo. Aquí no hay IPs, no hay paquetes, no hay protocolos… solo señales eléctricas, luz o radio.

- Cables (UTP, fibra óptica...)
- Señales inalámbricas (WiFi)
- Voltajes, modulaciones y frecuencia
- Hubs y repetidores

> [!TIP]  
> Para un pentester físico, esta capa es el terreno de ataques como **LAN Tapping**, sniffing en cableado, jammers WiFi, etc.

## 2️⃣ Capa de Enlace de Datos (Data Link Layer)

Aquí ya aparece algo fundamental: **la dirección MAC**.  
Esta capa se encarga de mover datos dentro de la misma red local (LAN) y de detectar/corregir errores básicos.

- MAC de origen y destino
- Control de flujo
- Corrección de errores (Frame Check Sequence)
- Protocolos como Ethernet, ARP[^1]

> [!CAUTION]  
> Ataques como **ARP Spoofing**, **MAC Flooding** o **ARP Poisoning** ocurren **exclusivamente en esta capa**.

## 3️⃣ Capa de Red (Network Layer)

Aquí ya hablamos de **IP**, **rutas** y **redes diferentes**.  
Es la capa encargada de mover paquetes entre redes distintas.

- Direccionamiento IPv4/IPv6
- Enrutamiento
- Subredes y máscaras
- Routers
- Protocolos ICMP, IP, OSPF, BGP

> [!IMPORTANT]  
> La inmensa mayoría de escaneos y reconocimiento de red (Nmap, traceroute…) ocurren aquí.

## 4️⃣ Capa de Transporte (Transport Layer)

Su función es garantizar (o no) que los datos lleguen correctamente a la aplicación.  
Aquí viven **TCP** y **UDP**.

- **TCP**
    - Conexión orientada
    - Three-Way Handshake
    - Reenvío de paquetes perdidos
    - Orden de entrega garantizado
- **UDP**
    - Sin conexión
    - Rápido, sin garantizar entrega
    - Ideal para streaming, juegos, VoIP

> [!NOTE]  
> Si la aplicación necesita confiabilidad → **TCP**  
> Si necesita velocidad y tolera pérdidas → **UDP**

## 5️⃣ Capa de Sesión (Session Layer)

Gestiona la **apertura, mantenimiento y cierre** de sesiones entre dos hosts.

- Establecimiento de sesión
- Control de autenticación básica
- Gestión de reconexiones
- Reanudación de sesiones

> [!TIP]  
> En términos prácticos, muchas funciones de esta capa hoy las asumen servicios de aplicación como HTTPS o SSH.

## 6️⃣ Capa de Presentación (Presentation Layer)

Se encarga de **cómo** se representan los datos para que la aplicación pueda entenderlos.

- Codificación de caracteres
- Serialización (JSON, XML)
- Compresión
- Cifrado/descifrado (TLS, SSL)

> [!WARNING]  
> Vulnerabilidades relacionadas con **malas implementaciones de cifrado**, parsing defectuoso o ataques de serialización ocurren aquí.

## 7️⃣ Capa de Aplicación (Application Layer)

Es donde realmente interactúa el usuario o el software.  
Aquí viven todos los protocolos que usas a diario:

- HTTP/HTTPS
- FTP
- SSH
- DNS
- SMTP/IMAP/POP3

> [!IMPORTANT]  
> La mayoría de vulnerabilidades explotables por pentesters (SQLi, XSS, LFI, RCE…) ocurren **en esta capa**, ya que dependen directamente de cómo se implementa un servicio.

# 🔎 Resumen visual

|Capa|Nombre|Ejemplos|Qué controla|
|---|---|---|---|
|7|Aplicación|HTTP, SSH, DNS|Servicios y apps|
|6|Presentación|TLS, JSON|Formato, cifrado|
|5|Sesión|RPC, NetBIOS|Apertura/cierre de sesiones|
|4|Transporte|TCP, UDP|Conectividad y puertos|
|3|Red|IP, ICMP|Rutas y direcciones|
|2|Enlace|Ethernet, ARP|Comunicación local + MAC|
|1|Física|Cable, WiFi|Señales y hardware|

---

# 📝 Resumen final

- El modelo OSI divide la comunicación en **7 capas**, cada una con su función.
- Comprenderlo te ayuda a **analizar tráfico**, **entender ataques** y **detectar vulnerabilidades**.
- Capa 3 y 4 son las más importantes para pentesting de red.
- Capa 7 es donde suelen estar las vulnerabilidades explotables.

> [!IMPORTANT]  
> El modelo OSI es tu mapa mental para entender _dónde ocurre cada ataque_, _cómo viajan los paquetes_ y _qué herramientas usar en cada nivel_.
