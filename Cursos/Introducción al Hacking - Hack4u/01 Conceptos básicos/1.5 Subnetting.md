# Introducción

El **Subnetting** es una técnica utilizada para dividir una red IP en subredes más pequeñas y manejables. Esto permite:

- Optimizar la utilización de direcciones IP.
- Facilitar la administración de la red.
- Mejorar la seguridad y el control del tráfico.

Cada subred se define mediante una **máscara de red**, que indica qué parte de la dirección IP corresponde a la red y qué parte corresponde a los hosts. Entender cómo funcionan estas máscaras y cómo se representan es fundamental para cualquier administrador de red o pentester.

> Comprender Subnetting es clave para interpretar rangos de IP, planificar redes y detectar posibles vectores de ataque.

---

# Cómo se interpreta una máscara de red

Una **máscara de red** indica qué bits de la dirección IP pertenecen a la red y cuáles a los hosts.  

Por ejemplo, la máscara `255.255.255.0` significa que:

- Los primeros 24 bits (los tres primeros octetos) identifican la **red**.
- Los últimos 8 bits identifican los **hosts** dentro de esa red.

En binario, la máscara se representa así:

```
11111111.11111111.11111111.00000000
```

> [!TIP]  
> Cada bit “1” corresponde a la parte de red, y cada bit “0” a la parte de host. Aprender a leer máscaras en binario te ayuda a calcular subredes rápidamente.

Con esta máscara, podríamos tener hasta 256 direcciones IP (2^8), pero restando la dirección de red y la de broadcast, quedan 254 hosts utilizables.

# CIDRs y cálculo total de hosts

El **CIDR (Classless Inter-Domain Routing)** es una forma flexible de representar máscaras de red usando un **prefijo**:

```
Dirección IP/Prefijo
Ejemplo: 192.168.1.1/24
```

- El número después de la barra indica la cantidad de bits que representan la red.
- Los bits restantes identifican los hosts.

## Cálculo de hosts disponibles

Para calcular el número de hosts:

1. Determina el número de bits de host (bits “0”).
2. Calcula 2^(n) – 2, donde n es la cantidad de bits de host (restamos 2 por la dirección de red y broadcast).

**Ejemplos:**

|CIDR|Bits de host|Total hosts|
|---|---|---|
|/28|4|2^4 – 2 = 14|
|/26|6|2^6 – 2 = 62|
|/22|10|2^10 – 2 = 1022|

# Máscaras de subred y clases de red

Aunque CIDR reemplaza la necesidad de clases fijas, es útil conocerlas:

|Clase|Primer octeto|Máscara predeterminada|Comentario|
|---|---|---|---|
|A|0-127|255.0.0.0|Redes muy grandes|
|B|128-191|255.255.0.0|Redes medianas|
|C|192-223|255.255.255.0|Redes pequeñas|

Además de estas clases, se pueden usar máscaras personalizadas para ajustar el tamaño de cada subred según necesidades específicas.

# Interpretación de rangos de red

Para trabajar con subredes es importante identificar:

1. **Network ID** → identificador único de la subred.
2. **Broadcast address** → dirección para enviar paquetes a todos los hosts.
3. **Rango de hosts** → direcciones IP que se pueden asignar a dispositivos.

**Ejemplo práctico:**

Red: `192.168.1.0/26`

- Máscara: `255.255.255.192`
- Network ID: `192.168.1.0`
- Broadcast: `192.168.1.63`
- Hosts disponibles: `2^6 – 2 = 62`

> [!TIP]  
> La fórmula general para calcular la broadcast: coloca todos los bits de host a 1.

---

# Redes extrañas y casos particulares

En redes reales, puede que te encuentres:

- Subredes con tamaños no estándar (por ejemplo /30, /29).
- Direcciones IP privadas, públicas o superpuestas.
- Rangos asignados por clientes que requieren auditoría.

Entender correctamente el rango de IP de cada subred es esencial para evitar conflictos, accesos no deseados o errores durante un pentest.

# 📝 Resumen rápido

- **Subnetting** → dividir redes grandes en subredes más pequeñas y eficientes.
- **Máscara de red** → define qué parte de la IP es red y qué parte host.
- **CIDR** → representación flexible con prefijo (/n).
- **Cálculo de hosts** → 2^(n) – 2, donde n = bits de host.
- **Network ID y Broadcast** → identificadores clave de cada subred.
- **Clases de red** → A, B y C (aunque CIDR es más usado).

> [!IMPORTANT]
> El dominio de Subnetting es **fundamental para administración de redes, pentesting y planificación de infraestructuras**, ya que determina cómo se segmenta y gestiona el espacio de direcciones IP.
