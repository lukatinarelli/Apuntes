# 📚 ¿Qué es el NSE?

El **Nmap Scripting Engine (NSE)** es una de las características más potentes de Nmap. Permite a los usuarios y desarrolladores escribir *scripts* sencillos, escritos en el lenguaje de programación **Lua**, para automatizar una vasta gama de tareas de red que van más allá del simple escaneo de puertos.

El NSE transforma a Nmap de un simple escáner de puertos y servicios a una herramienta de **detección de vulnerabilidades, explotación, reconocimiento avanzado y descubrimiento de backdoors**.

## Principales Funciones del NSE:

1.  **Detección avanzada de servicios:** Identificación precisa del software y la versión.
2.  **Detección de vulnerabilidades:** Comprobaciones no invasivas (y algunas invasivas).
3.  **Backdoors y Malware:** Búsqueda de puertas traseras comunes.
4.  **Fuzzing:** Envío de datos inesperados para probar la estabilidad.

# 🛠️ Uso práctico: Ejecución de Scripts

Para ejecutar scripts, se utiliza el parámetro `--script` de Nmap. Los scripts se encuentran en el directorio `nmap/scripts/`.

## 💻 Comandos para Ejecutar Scripts

El parámetro `--script` acepta nombres de scripts específicos, comodines (`*`), o categorías completas.

### 1. Por Nombre de Script

```Bash
# Ejecuta un script específico (ej. para forzar inicio de sesión en FTP)
nmap -p21 --script ftp-brute [TARGET]
```

### 2. Por Categoría (Conjunto de Scripts)

```Bash
# Ejecuta todos los scripts de la categoría 'default'
nmap -sV --script default [TARGET]
```

### 3. Múltiples Scripts o Categorías

Se pueden combinar scripts y categorías usando comas, o usando comodines para conjuntos específicos.

```Bash
# Combina scripts de vulnerabilidad y scripts para SMB
nmap -p445 --script vuln,smb-enum* [TARGET]
```

### 4. Argumentos para Scripts (`--script-args`)

Muchos scripts requieren argumentos (ej. credenciales, rutas de diccionario).

```Bash
# Ejemplo: Proporcionar un diccionario para el script de fuerza bruta
nmap --script http-brute --script-args userdb=users.txt,passdb=passwords.txt [TARGET]
```

# 📂 Categorías Clave de Scripts

El NSE organiza los scripts en categorías para facilitar su uso. El conocimiento de estas categorías es crucial para realizar escaneos efectivos.

|**Categoría**|**Propósito**|**Nivel de Intrusión**|
|---|---|---|
|**default**|Reconocimiento básico y detección de versiones. Se ejecuta automáticamente con `-sC`.|Bajo|
|**discovery**|Recopilación de información (enumeración SNMP, DNS, etc.)|Medio|
|**safe**|Scripts que no causarán fallos o consumos excesivos de recursos en el objetivo.|Bajo|
|**intrusive**|Puede ser detectado por Firewalls/IDS; realiza pruebas que consumen recursos.|Alto|
|**vuln**|Detección de vulnerabilidades conocidas (no explotación).|Variable|
|**exploit**|Intenta explotar activamente una vulnerabilidad (¡Usar con extrema precaución!).|Muy Alto|
|**brute**|Scripts de fuerza bruta (diccionario) para autenticación.|Alto|

> [!IMPORTANT]
> 
> Los scripts de las categorías intrusive, exploit y brute tienen una alta probabilidad de generar ruido o de causar interrupciones en sistemas sensibles. Úsalos solo con permiso explícito.

# 📝 Desarrollo de Scripts con Lua

Los scripts del NSE se escriben en **Lua**, un lenguaje ligero y rápido. Todo script NSE sigue una estructura básica: el **encabezado** (`HEAD`), la **regla** (`RULE`) y la **acción** (`ACTION`).

Para este módulo, hemos creado un script simple llamado `tcp-open-reporter.nse` que ilustra la estructura. El archivo completo se encuentra en el repositorio de recursos:

🔗 **Acceso al Script:** [tcp-open-reporter.nse](../../Recursos/NSE/tcp-open-reporter.nse)

## Bloques Funcionales del Script

Un script debe definir al menos una de las funciones: `portrule`, `hostrule`, `prerule`, o `postrule`. El ejemplo usa `portrule` para interactuar con puertos.

### 1. 📋 Encabezado (`HEAD`)

Define los metadatos necesarios para Nmap, como la descripción y la categorización.

```lua
description = [[ Script de ejemplo que enumera y reporta puertos abiertos por TCP ]]
categories = {"discovery", "safe"}
```

- **`description`**: Texto que se muestra cuando se usa `nmap --script-help`.
- **`categories`**: Crucial para que el script se ejecute cuando se invoca una categoría (ej: `default`, `safe`).

### 2. 🎯 Regla (`RULE`)

Define la lógica que decide **cuándo** se debe ejecutar la `action`. Si la función devuelve `true`, se ejecuta la `action`.

```Lua
portrule = function(host, port)
    return host.protocol == "tcp"
      and port.state == "open"
end
```

- **`portrule`**: Indica a Nmap que se ejecute una vez por cada puerto escaneado.
- **Lógica**: Solo devuelve _true_ (y ejecuta la acción) si el puerto es TCP y su estado es `open`.

### 3. ✍️ Acción (`ACTION`)

Contiene la lógica principal que se ejecuta si la `RULE` fue positiva. El valor devuelto se imprime en la salida final de Nmap.

```Lua
action = function(host, port)
    return string.format("--> [REPORTE] Puerto TCP %d está abierto", port.number)
end
```

- **`string.format`**: Función de Lua para dar formato al texto de salida, incluyendo el número de puerto encontrado.

## Notas Importantes

> [!NOTE] 
> Para que Nmap lo encuentre, debes colocar el archivo `.nse` dentro de tu directorio de scripts de Nmap (generalmente `/usr/share/nmap/scripts/` en Linux o donde lo hayas instalado).

**Indexación:** Después de añadir o modificar scripts, es recomendable actualizar la base de datos de scripts de Nmap para asegurar que se carguen correctamente:

```Bash
sudo nmap --script-updatedb
```
