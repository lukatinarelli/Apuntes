# 📚 Explicación teórica: El poder de /dev/tcp

La enumeración de puertos no siempre requiere herramientas externas como Nmap, que dejan una firma detectable. Una alternativa avanzada y sigilosa en sistemas **Unix/Linux** es aprovechar los **descriptores de archivo (File Descriptors)**.

Los descriptores de archivo son la forma en que el sistema operativo maneja las conexiones a recursos (archivos, *sockets*, dispositivos). El *pseudodispositivo* especial **/dev/tcp** permite que Bash abra una conexión TCP saliente a un host y puerto específicos, tratándola como si fuera un archivo que se puede leer o escribir.

## ¿Cómo funciona?

Al intentar abrir el "archivo" `/dev/tcp/<ip>/<puerto>`, el *shell* de Bash (específicamente la versión compatible con esta característica, como Bash 4+) intentará realizar el *three-way handshake* TCP con el destino.

* **Si el puerto está abierto:** La apertura del descriptor de archivo será exitosa (`$? = 0`).
* **Si el puerto está cerrado:** La conexión fallará, devolviendo un código de error.

# 🛠️ Uso práctico: Creación del Script Bash

Hemos creado un script de Bash, llamado `portScan.sh`, que automatiza esta verificación a través de un rango de puertos. Es un excelente ejemplo de escaneo **sin dependencias externas**.

🔗 **Acceso al Script Completo:** [Ver código fuente: portScan.sh](../Recursos/Scripts/portScan.sh)

## Análisis del Corazón del Script

El núcleo de la técnica reside en la función `checkport`, donde se manipulan los descriptores de archivo.

### 1. 🗂️ Apertura del Descriptor de Archivo

El comando crucial es la apertura del descriptor de archivo **3**:

```bash
(exec 3<> /dev/tcp/$1/$2) 2>/dev/null
````

- **`exec 3<>`**: Abre el descriptor de archivo número 3 para lectura y escritura (`<>`).
- **`/dev/tcp/$1/$2`**: La ruta al pseudodispositivo, con `$1` (IP) y `$2` (Puerto) como variables.
- **`2>/dev/null`**: Redirecciona la salida de error (`stderr`) al vacío. Esto es vital, ya que si el puerto está cerrado, Bash generará un error ruidoso. Al silenciarlo, solo nos interesa el código de salida.

### 2. 🚦 Verificación del Código de Salida

Inmediatamente después del intento de conexión, se comprueba el código de salida de Bash:

```Bash
if [ $? -eq 0 ]; then
    echo "[+] Host $1 - Puerto $2 abierto"
fi
```

- **`$?`**: Contiene el código de salida del último comando ejecutado. Si es **0**, significa éxito (conexión TCP exitosa).

### 3. 🧹 Cierre de Descriptores

Es imprescindible cerrar los descriptores de archivo abiertos para liberar recursos:

```Bash
exec 3<&- 3>&-
```

# ⚠️ Advertencias y Limitaciones

> [!WARNING]
> **Fiabilidad y Velocidad:** Este método es intrínsecamente más lento que Nmap y menos robusto, especialmente cuando se escanean miles de puertos, ya que crea un proceso por cada puerto. Además, requiere Bash 4.0 o superior y no funcionará en shells como Zsh o Fish a menos que se fuerce la ejecución en Bash.

> [!IMPORTANT]
> **Sigilo:** Aunque esta técnica no utiliza la firma de Nmap, la velocidad por defecto del script puede seguir siendo detectada por un IDS/IPS, ya que sigue siendo un alto número de paquetes SYN en poco tiempo.
