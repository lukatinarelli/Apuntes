# 📚 Explicación teórica: ¿Por qué enumerar subdominios?

Los subdominios (ej. `api.dominio.com`, `staging.dominio.com`) a menudo apuntan a diferentes servidores o servicios que pueden tener configuraciones de seguridad más débiles que el dominio principal. Expandir la superficie de ataque (Attack Surface) mediante la identificación de subdominios es crucial para encontrar vectores de ataque potenciales.

Las técnicas de enumeración se dividen en dos categorías:

1.  **Pasiva:** Recolección de datos ya indexados públicamente (registros DNS, certificados SSL/TLS). Es silenciosa y no toca el objetivo.
2.  **Activa:** Envío de tráfico (fuerza bruta) al servidor DNS del objetivo. Es ruidosa y detectable.

---

# 🛠️ Herramientas de Enumeración Pasiva

Estas herramientas aprovechan datos públicos. La clave aquí es la **transparencia del certificado SSL/TLS (Certificate Transparency Logs)**. Cada vez que se emite un certificado SSL para un subdominio, queda registrado públicamente.

## 1. CTFR (Certificate Transparency FindeR)

CTFR es una herramienta Python que abusa de la transparencia de los certificados SSL para listar subdominios asociados a un dominio.

### Paso 1: Configuración (Entorno Virtual)

Es obligatorio instalar herramientas Python en un entorno virtual (`venv`) para evitar conflictos de librerías.

```Bash
# 1. Crear entorno virtual
python3 -m venv .venv 

# 2. Activar el entorno
source .venv/bin/activate 

# 3. Instalar dependencias
pip install -r requirements.txt
````

### Paso 2: Ejecución

Se requiere el argumento `-d` para el dominio objetivo.

```Bash
python3 ctfr.py -d tinder.com
# Ejemplo de salida: *.swipelife.tinder.com, go.tinder.com, help.tinder.com, etc.
```

🔗 **Repositorio CTFR:** https://github.com/UnaPibaGeek/ctfr

## 2. Sublist3r

Sublist3r combina múltiples motores de búsqueda (Google, Yahoo, Bing, Netcraft, etc.) y herramientas como `Phonebook.cz` para encontrar subdominios de forma pasiva.

```Bash
python3 sublist3r.py -d tinder.com
# Muestra el total de subdominios únicos encontrados por varias fuentes.
```

🔗 **Repositorio Sublist3r:** https://github.com/huntergregal/Sublist3r

# 🔨 Herramientas de Enumeración Activa (Fuerza Bruta)

Estas herramientas envían peticiones a la red y son detectables, pero son necesarias para encontrar subdominios que no están listados en registros públicos.

## 1. Gobuster (Vhost Mode)

`Gobuster` es rápido y eficiente, programado en Go, ideal para tareas que requieren muchas conexiones (sockets). El modo `vhost` (Virtual Host) está diseñado específicamente para enumerar subdominios mediante fuerza bruta.

```Bash
gobuster vhost -u https://tinder.com -w /usr/share/SecLists/Discovery/DNS/subdomains-top1million-5000.txt -t 20
```

- **-u:** URL objetivo
- **-w:** Diccionario de palabras
- **-t 20:** 20 hilos (paralelismo) para acelerar el proceso

> [!NOTE]
> 
> Para hacer la salida más legible, es común filtrar los códigos de estado HTTP que no son relevantes (ej. 403 Forbidden, que a menudo solo indica que el subdominio no existe o está protegido).
> 
> ```Bash
> ... | grep -v "403" 
> ```

**🔗 Repositorio Gobuster:** https://github.com/OJ/gobuster

🔗 **Diccionario SecLists:** https://github.com/danielmiessler/SecLists

## 2. Wfuzz (Fuzzing)

`Wfuzz` es una herramienta especializada en _fuzzing_ (inyección de _payloads_ en un parámetro) que también puede usarse para la enumeración de subdominios.

### 🎯 El Placeholder `FUZZ`

Cuando se usa `wfuzz` para subdominios, el placeholder **`FUZZ`** se utiliza para indicar dónde debe la herramienta inyectar cada línea del diccionario.

```Bash
wfuzz -c -t 20 -w /usr/share/SecLists/Discovery/DNS/subdomains-top1million-110000.txt -H "Host: FUZZ.tinder.com" http://tinder.com
```

- **-c:** Muestra salida con color
- **-t 20:** 20 hilos
- **-w:** Diccionario de palabras (subdominios)
- **-H "Host: FUZZ.tinder.com":** Inyecta la palabra del diccionario donde está FUZZ.

### Filtrado de Códigos

`Wfuzz` ofrece comandos dedicados para filtrar códigos de estado (es más limpio que usar `grep`):

|**Comando**|**Acción**|**Ejemplo**|
|---|---|---|
|**`--hc=CODE`**|**H**ide **C**ode (Ocultar código)|`--hc=403`|
|**`--sc=CODE`**|**S**how **C**ode (Mostrar código)|`--sc=200,301,302`|

🔗 **Repositorio Wfuzz:** https://github.com/xmendez/wfuzz

# 📝 Conclusión del Reconocimiento

> [!TIP]
> **Combinación de Herramientas:** Es vital usar varias herramientas (pasivas y activas) y diccionarios, ya que ninguna por sí sola es exhaustiva. Juntar los resultados maximiza la superficie de ataque antes de iniciar la auditoría.
