# ✔️ Introducción general

Un keylogger es un componente software diseñado para **interceptar y registrar las pulsaciones del teclado** de un sistema.  
En el contexto de la seguridad ofensiva, permite analizar cómo responde un entorno ante la monitorización de la entrada del usuario, estudiar patrones de uso o evaluar el impacto que tendría una filtración de credenciales si un actor malintencionado lograra instalar un sistema similar.

El objetivo de este módulo es comprender **la arquitectura interna**, **la lógica de captura**, y **el mecanismo de reporte remoto**.

---

# 🧱 1. Arquitectura general de un keylogger

Un keylogger funcional suele dividirse en **cuatro subsistemas principales**:

## 1.1 Captura de pulsaciones

Se encarga de **escuchar los eventos** generados por el teclado.  
Una biblioteca habitual para este propósito en Python es `pynput`, que permite:

- Suscribirse a eventos de pulsación (`on_press`)
- Extraer caracteres imprimibles
- Identificar teclas especiales (Shift, Alt, Space, Enter, etc.)

Ejemplo conceptual:

```python
def start(self):  # Inicia el sistema de escucha del keylogger
    keyboard_listener = pynput.keyboard.Listener(on_press=self.pressed_key)
    # Listener encargado de interceptar cada pulsación del teclado.

def pressed_key(key):
    # Se ejecuta cada vez que se pulsa una tecla
    ...
```

La función se invoca de manera asíncrona según el sistema detecta entrada del dispositivo.

## 1.2 Normalización del input

El registro debe transformar cada evento en un formato legible.  
Existen dos escenarios:

- **Caracteres imprimibles** → se añaden directamente (`a`, `b`, `7`, `%`, etc.)
- **Teclas especiales** → se representan con un identificador claro:  
    `[Enter]`, `[Space]`, `[Backspace]`

Ejemplo conceptual:

```python
if key.char:          # tecla imprimible
    log += key.char
else:                 # tecla especial
    log += f"[{key.name}]"
```

Esta normalización permite generar un registro coherente para auditorías posteriores.

## 1.3 Almacenamiento temporal y planificación

Las pulsaciones no suelen enviarse inmediatamente; se almacenan en un **búfer interno** (`log`) y se procesan en intervalos de tiempo definidos.

El mecanismo habitual es:

- Acumular las pulsaciones en memoria
- Cada cierto tiempo (ej. 45 segundos), enviar el contenido
- Vaciar el búfer
- Repetir el ciclo mientras el programa siga activo

Esto se gestiona con un **temporizador (Timer)** que se auto-reactiva:

```python
def report():
    enviar_log(...)
    limpiar_log()
    reactivar_temporizador()
```

Este proceso independiente permite que el listener siga funcionando sin interrupciones.

## 1.4 Mecanismo de reporte remoto

El objetivo del reportador es **sacar la información del equipo** de forma periódica.  
Los mecanismos típicos son:

- Envío por correo electrónico
- Envío HTTP a un servidor remoto
- Escribir en archivos ocultos
- Uso de sockets (TCP, UDP, túneles, etc.)

En este módulo se utiliza **correo electrónico por SMTP**, ya que permite:

- Comunicación cifrada (SSL)
- Entrega garantizada
- Integración sencilla con Python

El mensaje enviado es simplemente el contenido del registro:

```python
def send_email(subject, body):
    # Empaqueta el contenido
    # Autentica contra el servidor SMTP
    # Envía el mensaje al destinatario
```

Para proveedores modernos (como Gmail), es obligatorio usar **contraseñas de aplicación**, ya que bloquean accesos directos desde scripts.

# 🧲 2. Ciclo de vida del keylogger

Un keylogger bien diseñado sigue una secuencia lógica:

## 2.1 Inicialización

Se definen parámetros esenciales:

- Intervalo de envío
- Cuenta de correo remitente
- Destinatarios
- Contraseña de aplicación
- Variables de estado (como `log` o indicadores de apagado)

## 2.2 Activación del listener

Se activa el componente que captura pulsaciones:

- Suscripción a eventos
- Ejecución en segundo plano
- Inicio del temporizador de reportes

En este momento, el programa queda "vigilando" todo el input del usuario.

## 2.3 Captura continua

Cada evento genera una llamada a la función encargada de registrar la tecla:

```
tecla pulsada → función pressed_key → se añade al log
```

El proceso ocurre miles de veces por minuto sin bloquear el programa.

## 2.4 Reporte periódico

Cada vez que se cumple el intervalo:

- El contenido acumulado se envía por email
- El búfer se limpia
- El temporizador se reactiva y espera al siguiente ciclo

Este es el núcleo del funcionamiento autónomo de la herramienta.

## 2.5 Finalización controlada

Para evitar dejar procesos huérfanos, se implementa un sistema de apagado:

- Reset del indicador de ejecución
- Cancelación de temporizadores activos
- Finalización del listener

Esto permite detener el programa con `Ctrl + C` sin romper la ejecución.

Ejemplo conceptual:

```python
def shutdown():
    detener_temporizador()
    avisar_al_listener()
```

# 📦 3. Estructura de archivos recomendada

Para mantener una separación limpia entre lógica y ejecución:

```
/keylogger/
│
├── keylogger.py   ← contiene la clase y toda la lógica interna
└── main.py        ← instancia el keylogger y lo ejecuta
```

Esta separación permite:

- Mantener los apuntes limpios
- Versionar la herramienta de forma modular
- Facilitar pruebas, modificaciones y ampliaciones

# 🔍 4. Consideraciones técnicas

Al desarrollar un keylogger en Python hay varios puntos importantes:

## 4.1 Limitaciones del lenguaje

- Necesita bibliotecas externas (`pynput`, `email.mime`)
- No es la opción más sigilosa (interpretable, fácil de detectar)
- Dependencia de entorno gráfico o permisos especiales según el sistema

## 4.2 Restricciones del sistema

- Algunos entornos (como Wayland) impiden la captura de pulsaciones
- Antivirus y EDR pueden detectar patrones de keylogging
- Las APIs de correo requieren contraseñas específicas

## 4.3 Buenas prácticas internas

- Búfer pequeño para evitar acumulación excesiva
- Identificación clara de teclas especiales
- Temporizadores independientes y cancelables
- Envió fiable a través de SMTP con SSL

---

# 📌 Resumen final del funcionamiento

1. Se inicia la clase principal del keylogger
2. Se abre un listener que detecta cada tecla pulsada
3. Las pulsaciones se normalizan y se añaden a un registro
4. Cada _X_ tiempo, un temporizador envía ese registro por email
5. El registro se vacía
6. El temporizador se reinicia automáticamente
7. Con `Ctrl+C` se detiene el keylogger de forma ordenada

Este diseño modular permite expandir funcionalidades, como:

- Cifrado de logs
- Detección de patrones
- Persistencia en el sistema
- Comunicación por HTTP o sockets
- Ocultamiento avanzado
